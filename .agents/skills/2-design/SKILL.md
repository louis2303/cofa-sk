# 2. 업무 설계 및 실행 계획

## 목적
과제에 맞는 **가장 작은 실행 가능한 작업 흐름**을 설계한다. 불필요한 기능은 만들지 않는다.

## 절차
1. 과제 지시사항과 확정된 요구사항을 확인한다. 웹/데이터/문서/Agent 등 유형을 미리 가정하지 않는다.
2. 목표 → 입력 → 처리 → 결과물 → 검증 방법을 연결한다.
3. 작업을 작은 단위로 나누고 필수 기능부터 우선순위를 정한다. 각 단계에 완료 기준을 둔다.
4. 이미 제공된 도구와 프로젝트 구조를 먼저 확인한다. 추가 도구/MCP/외부 코드가 꼭 필요한 경우에만 제안한다.
5. 프롬프트는 '목표 + 근거 + 작업 범위 + 검증 + 보고' 순으로 구성한다. 필요할 때만 예시(Few-shot)와 단계별 작업 분리를 사용한다.
6. **과제가 실제 AI Agent 구축을 요구한다면** 아래 요소 중 필요한 것만 검토한다.
   - Rule: 항상 지킬 행동 기준
   - Skill: 상황별 반복 업무 절차와 선택 조건
   - Tool: 계산/조회/검색 등 실행 기능
   - 판단: 상황에 맞는 Skill/Tool 선택
   - 업무지식: 문서/규정 검색과 근거 활용
   - 기억: 대화 종료 후 저장/조회가 필요한 정보
   - 자동화: 시간/이벤트 시작 조건과 실행기록
   - 승인/통제: 중요한 실행 전 사람 확인
7. 필요한 경우 spec.md에 구현 세부 사항을, PLAN.md에 작업 순서/진행 상태를 기록한다. 기존 과제의 지정 문서가 있으면 그걸 우선한다.

## 출력
- 필수 작업과 우선순위
- 단계별 완료 기준 및 테스트 방법
- 확인이 필요한 결정
- 바로 사용할 다음 작업 지시문 초안

## 주의
- 고객용 Agent의 장기기억과 Codex 작업용 requirements.md를 혼동하지 않는다.
- Skill/Tool/기억/자동화는 **필요성 확인 후** 제안한다.
- 계획만 길게 세우느라 구현을 지연시키지 않는다.
