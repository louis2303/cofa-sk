# 1. 요구사항 분석

## 목적
사용자가 문제를 정의하고 확인할 질문을 선택할 수 있도록 **근거 있는 요구사항 목록**을 만든다.

## 절차
1. 실제 과제 지시사항, README, 제공된 파일 및 제출 조건부터 확인한다.
2. 다음을 분리해 정리한다.
   - 해결해야 할 문제와 사용자
   - 필수 결과물·기능·제출 형식
   - 입력 자료·수치·계산 규칙
   - 금지·제약·예외·경계 조건
3. 각 항목은 확인 가능한 출처(파일명, 위치, 담당자 답변)를 표시한다.
4. **확정 / 불명확 / 자료에 없음**으로 구분한다. 모르는 내용을 지어내지 않는다.
5. 구현에 영향을 주는 질문만 중요도순으로 제안한다. 담당자가 결정할 사항을 사용자가 대신 추측하지 않게 한다.
6. 사용자에게 요약 결과와 질문을 먼저 보여준다. 초기 분석 단계에서는 구현하지 않는다.
7. 사용자가 담당자 답변을 알려주면 원문과 구분해 확정 요구사항을 갱신한다. 필요하면 requirements.md에 기록한다.

## 출력
- 핵심 목표와 필수 결과물
- 근거를 포함한 확정 조건
- 확인이 필요한 조건과 우선 질문
- 구현 전에 결정해야 할 사항

## 주의
- 과제에 없는 기능을 추가하지 않는다.
- 업무 담당자 DM을 읽었다고 가정하지 않는다.
- 요구사항 충돌은 조용히 덮어쓰지 말고 표시한다.
