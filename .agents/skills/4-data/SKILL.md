# 4. 데이터 분석 및 검증

## 목적
원본 데이터와 과제 기준을 유지하면서 재현 가능한 분석 결과를 만든다.

## 절차
1. 과제 지시사항과 입력 파일을 먼저 확인한다. 분석 목표, 결과물, 계산 규칙, 단위와 기간을 구분한다.
2. 원본을 덮어쓰지 않는다. 행/열 수, 컬럼명, 자료형, 결측치, 중복, 이상값, 시간 형식과 단위를 점검한다.
3. 전처리 규칙을 먼저 명시한다. 제외/대체/변환한 행과 값의 기준을 기록한다. 근거 없이 이상치를 삭제하거나 결측값을 채우지 않는다.
4. 분석 목표에 필요한 최소 작업부터 수행한다. 정렬, 필터링, 집계, 비율/증감률, 통계, 모델링 중 해당 과제에 필요한 방법만 선택한다.
5. 계산식, 분모, 기준 시점, 반올림, 경계 조건을 점검한다. 가능한 경우 원본 일부를 수작업 또는 독립적인 코드로 재계산한다.
6. 그래프가 필요하면 과제 목적에 맞는 형태를 선택하고 축, 단위, 범례, 시간 순서, 정렬 기준을 확인한다. 원본 수치와 그래프 값의 일치 여부를 점검한다.
7. 사실(계산된 결과), 해석(시사점), 불확실성(확인 필요)을 구분한다. 상관관계를 인과관계로 단정하지 않는다.
8. 지정된 형식으로 결과를 저장하고 파일 경로를 확인한다. 전처리 전후 행 수, 핵심 계산, 검증 결과와 한계를 간결히 보고한다.

## 상황별 확인
- 시계열: 시간 순서, 간격, 누락 구간, 중복 시각, 시작/종료 경계
- 비율/변화율: 기준값, 0으로 나누기, %와 %p 구분
- 실험 데이터: 조건별 반복, 단위, 측정 범위, 변수 간 혼동
- 예측 모델: 데이터 누수 방지, 학습/검증 구분, 평가 지표의 의미
- 보고서: 출처, 계산값, 그래프, 해석이 서로 일치하는지 대조

## 출력
- 원본 데이터 점검 결과
- 적용한 전처리 및 분석 기준
- 생성한 결과물과 저장 경로
- 실제 검증 결과와 확인이 필요한 사항

## 주의
- 분석을 위해 필요하지 않은 복잡한 모델이나 도구를 추가하지 않는다.
- 과제에서 정한 전처리 기준과 출력 형식을 임의로 바꾸지 않는다.
- 실제 확인하지 않은 수치, 그래프, 모델 성능을 만들어내지 않는다.
