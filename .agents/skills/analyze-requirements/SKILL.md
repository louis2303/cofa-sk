# 요구사항 분석
1. 작업 루트의 README, 기존 코드, 제공된 데이터와 환경·제출 제한을 읽고 원본은 보존한다.
2. 필수·선택 기능, 사용자·관리자 역할, 입력·출력, 예외, 품질 기준과 명시된 근거를 정리한다.
3. 누락·충돌·모호한 업무 규칙을 찾는다. 사실, 가정, 개선 제안을 구분하고 담당자 결정이 필요한 것은 [담당자 확인 필요]로 표시한다.
4. 각 쟁점의 가능한 대안과 구현·일정 영향을 설명하며 사용자 확인 및 담당자 답변을 반영한다.
5. Templates/Analysis.md를 참고해 실제 프로젝트 Docs/Analysis.md에 해석·미결사항·주요 의사결정을 기록한다.
6. PRD 작성을 위한 범위를 제시하되 실제로 제공되지 않은 비즈니스 규칙을 만들어 넣지 않는다.

예: '최적화'라는 단어만으로 목적함수를 확정하지 않고 평가 기준·강한 제약·우선순위를 구분해 확인한다.
완료 기준: 요구별 근거와 해결해야 할 쟁점이 추적 가능하다.
