# 종합 검증
1. README, Prd.md, Spec.md, Architecture.md, Algorithm.md(해당 시), 실제 코드·진행 기록을 대조한다. 이전 AI의 완료 주장을 검증 근거로 취급하지 않는다.
2. Templates/Testplan.md를 참고해 Docs/Testplan.md에 요구 ID, 우선순위, 입력/절차, 기대 결과, 실행 도구, 합격 기준을 작성한다.
3. 필수 기능 누락, 강한 제약, 경계값·빈 데이터·중복·실패·권한 우회·재시작 등 위험을 자체 검토한다.
4. 사용자와 Testplan 초안을 검토하고 추가 시나리오를 반영해 승인받은 다음 종합 테스트를 실행한다. 구현 중 기본 단위/API 테스트는 승인을 기다리지 않는다.
5. 알고리즘 결과, 단위/API/DB/계약, 사용자/관리자 권한, UI·E2E·반응형/접근성, 오류 처리, 성능, 회귀, 최종 산출물을 프로젝트에 맞춰 검증한다.
6. pytest·Playwright·Locust 등을 사용 가능성과 비용에 맞춰 선택한다. 설치만 하고 실행하지 않은 테스트는 통과 처리하지 않는다.
7. Docker를 사용했다면 이미지 빌드·컨테이너 시작·포트·환경변수·연동·재시작을 확인한다.
8. 실패 시 재현→원인 분석→수정→재검증을 진행하고 실제 명령·핵심 로그·통과/실패/미검증을 Progress.md에 남긴다.
9. 최종 검토에서는 최초 설계가 아니라 실제 코드와 테스트를 기준으로 어떤 방법을 썼고 왜 선택했는지, 다른 대안보다 유리한 점과 한계, 성공·실패·미검증 내용을 쉬운 한국어로 설명한다. 근거가 없는 효과는 추정으로 구분한다.
10. 최종 실행 환경과 요구된 제출 파일·경로·형식·금지사항을 확인한다.

시간 부족 시 필수 요구, 핵심 흐름, 데이터·권한 무결성부터 확인하고 부하/미관 테스트는 후순위로 둔다.
