# 프론트 기술 및 UI/UX
1. 승인된 Prd.md, Spec.md, Architecture.md, 기존 화면/코드를 확인한다.
2. 선택된 프론트 기술 스택이 기능·개발 시간·실행환경에 적절한지 검토하고 변경이 필요하면 근거와 대안을 제시해 승인받는다.
3. 사용자와 관리자의 대표 작업 흐름, 화면·내비게이션 구조, 주요 인터랙션을 정한다.
4. 색상·타이포그래피·간격·컴포넌트·표/폼의 일관성을 유지한다. 실제 사용자의 정보 탐색과 조작 편의를 우선한다.
5. 로딩·빈 데이터·입력 오류·서버 실패·권한 부족 상태와 피드백을 설계한다.
6. 반응형, 기본 접근성, 키보드 조작과 가독성을 확인한다. 필요 시 실제 브라우저로 개선점을 반복 검증한다.
7. 장식적 효과나 신규 라이브러리 때문에 필수 기능 구현을 지연하지 않는다.

예: 데이터가 없는 목록은 빈 화면 대신 명확한 안내와 조건 초기화 동작을 제공한다.
