# 기능 구현
1. 현재 Spec.md, Architecture.md, Plan.md와 해당 시 Algorithm.md, 기존 코드를 확인한다.
2. 우선순위 높은 기능을 입력→처리→API/저장→화면(해당 시)까지 실제 연결되는 작은 작업으로 분해한다.
3. 로직·API·스키마·DB 접근·UI를 역할에 맞게 분리하며 프로젝트 규모에 맞는 구조를 선택한다.
4. 관리자 기능이 필요하면 관리자 UI와 API를 연결하고 서버에서 인증/권한을 검증한다.
5. 각 기능의 단위/API/예외 테스트를 직접 실행하고 실패 시 수정→재실행한다. 테스트 결과를 주장만 하지 않는다.
6. 실제 서버와 브라우저에서 핵심 경로를 확인한다. 포트·실행 명령·오류를 파악한다.
7. Docker를 사용하기로 했다면 Dockerfile/구성 파일을 작성하고 빌드 및 실행·연결을 점검한다. 불허 시 무리하게 설치하지 않는다.
8. 주요 기능 완료·오류·수정·재검증 시 Docs/Progress.md를, 파일 구조 변경 시 Filereview.md를 갱신한다.
9. 업무 의미나 중대한 아키텍처 변경은 사용자에게 근거와 영향을 제시해 승인받는다.

완료 보고: 실행된 기능, 확인한 테스트와 결과, 남은 위험을 간결히 제시한다.
